# Frozen parameters

There are two kinds:
- **values** fixed now;
- **rules** fixed now, whose values come from the pilot or the scripted runs (#12) and are added later as a dated amendment.

Everything here is identical across options and layouts.

## Values fixed now

| Parameter | Value |
|---|---|
| Seeds | 1, 2, 3 per (instance, option, layout, model) in the main block; seed 1 in every one-seed block (pilot, pagination cell, calibration set). Passed to the API where seeding is supported; where it is not (Anthropic), the seed only labels the repetition |
| Sampling and reasoning | per model, the vendor's recommended settings for agentic tool use (temperature, top-p, thinking or reasoning mode and its budget), with sources, in the config from #8; frozen before the pilot. Per-model settings do not confound option effects, which are estimated within each model |
| Prompt caching (decided 1 Nov) | Claude models only, identically in every option, with the 1-hour TTL, so that long tool calls don't change cost or latency by option. It changes no prompt content. Input tokens, P3 and `{TOKEN_BUDGET}` count the full prompt: uncached + cache-write + cache-read tokens, each also recorded separately. The cost outcome is tokens; dollars are reported only as campaign spend |
| Output cap | 8,000 characters per tool result entering the context, truncated identically for every tool and option |
| Instances | 25 disjoint regions × 2 target periods (June–August of two distinct years within 2003–2022, by the period rule below); the resulting instance manifest is frozen before the pilot; region bounds midway between cell centres; 10 pilot instances flagged (#5) |
| Correct (for the end-to-end outcome) | IoU of the agent's and the reference's cell-day masks ≥ 0.9 on instances with reference events (it scales smoothly with few events, unlike F1); no cell-day = 1 in the mask on event-free instances |
| Model backends (operator decision, 1 Nov) | every open-weight model is served by two vLLM backends (site-b and the team's site-a stacks). A session stays on one backend. When both have capacity, the scheduler picks the backend that keeps the (model, option, layout) cell closest to that model's overall backend share. Each run records the backend, base URL, API model id, real checkpoint and `system_fingerprint` |
| Backend in the analysis | primary: not a factor (contrasts paired by region within model); secondary mixed model: backend as a fixed effect; sensitivity: per open-weight model, its majority backend only, reporting any change of direction or of smallest-effect status; backend shares reported per cell |
| Invalid tool-call arguments | unparseable arguments are replaced in the history by a valid placeholder, and the agent receives an "invalid arguments" tool result. This counts as a tool round, identically for every model and option. Counted per run (`invalid_tool_args_rounds`) |
| Run order and drop order (decided 1 Nov; replaces the proposal's "first the pagination cell, then S2") | The campaign runs in two blocks, each in randomised order. The block structure makes the drop order automatic: whatever is unfinished when time runs out is always the lowest-priority remainder.
  - **Block 1, protected:** the main S1 cells and the pagination cell, interleaved. Never dropped. The pagination cell is the evidence for the complete-listing remedy.
  - **Block 2, S2, in two tiers.** Tier A: Qwen3.8-27B, Claude Haiku 5.5 and Claude Sonnet 5.5, which keeps the pilot model and the cheaper/stronger tier pair of H4. Tier B: the other four models.
  - **If time runs out,** S2 is first reduced to tier A. Unfinished runs are reported, never imputed.

  Options stay randomised within every block and tier, so option contrasts are unaffected. Only layout and model comparisons are time-ordered; they are secondary or descriptive. |
| I/O mode of oneclient (from #10 Q7) | proxy I/O, auto-selected on site-g and site-f; direct I/O is unusable from the run host. Recorded per run |
| Enforcement overhead (added 1 Nov, before any agent run) | the enforced data paths cost time: a gate for T, T-unpaginated and D, a sidecar mount for M. Scripted runs with and without enforcement (k ≥ 5, same concurrency) measure it per option and layout. Wall-time contrasts are reported as measured, with this overhead stated beside them; tokens, correctness and bytes are unaffected |
| Bytes moved per run (from #10 Q6) | the agent container's own network-namespace counter (`eth0` rx bytes, before and after the run), not the host NIC, so concurrent runs are attributed separately. For M, the oneclient sidecar's namespace counter. T, D and M read directly from the data provider, so no on-the-fly replication occurs; replication occurs only in M+ |
| TLS mode of oneclient (operator decision, 1 Nov) | `--insecure` for the whole campaign, including the pilot and calibration runs. It is not changed during the campaign, so M carries no time-varying condition. Recorded per run |
| H3 test (fault-injection fidelity) | each option is calibrated against two records: the **default** one (Onedata file-access audit log, file-level) and the **switched-on** one (Traefik access log with `Range` for T and D; oneclient `--log-read-write-perf` in the sidecar for M). The threshold, recall and precision ≥ 0.9, applies per option × layout × record × condition (cold; warm buffer and prefetch on, M only) **over the fault types observable by design** for that record, as classed in `icsa/faults/OBSERVABILITY.md` before any calibration run. Recall over all faults is reported, not tested. Cells whose class needs the live audit log are classed from the live check before the calibration runs, with a timestamp.
  - **Non-testable cells:** a cell with no observable fault type is reported as not testable. The audit log in S2 is one: the single file is opened either way and the log has no offsets, so sub-file omissions are unobservable there by design.
  - **D:** the fault types observable under D are never-downloaded files; its cells are tested on those.
  - **Allocation:** the seeded matrix in `icsa/faults/matrix.py`: each applicable fault type gets ceil(60 / number of types) replicates, plus 30 fault-free runs, per option × layout × condition. Every planned run is run once; there is no stopping rule and no run is added after seeing results.
  - **Decision rule:** recall = detected faulted runs / faulted runs; precision = true flags / all flags, fault-free runs included. A cell passes if both **point estimates** are ≥ 0.9; Wilson and cluster-bootstrap intervals are reported beside them. A cell in which nothing is flagged has recall 0 and undefined precision, and fails. The two-record design was approved by the operator on 1 Nov; it revises H3. |
| Smallest effects that count for the decision guide | 10 percentage points in omission rate or coverage share; a factor of 2 in cost |
| Event matching (P2, as implemented in `icsa/scoring/events.py`) | an event is the set of cell-days active in the per-cell mask on the event's days. A candidate pair shares at least one cell-day. Matching is one-to-one: the most pairs first, then the greatest total of shared cell-days. F1 = 2·TP / (agent events + reference events). An agent with no events on an instance with reference events scores F1 = 0. F1 is undefined on event-free instances, which are scored by false alarm |
| Counterfactual decomposition | for a finished run with an analysed extent, the reference is re-run on exactly the data the run analysed within the required extent: percentiles from the baseline days available, missing target days treated as no data. **Computation discrepancy:** F1 of the agent's output against this counterfactual. **Omission discrepancy:** F1 of the counterfactual against the full-data reference. They are reported separately, never added. Undefined for a run with no analysed extent or where the F1 is undefined |
| Infrastructure failures | **Eligible:** a model endpoint or server-side knowledge-plane error that persists after the transport retries; a sandbox crash not caused by agent code; a failed Onedata health check before or after the run. **Never:** slowness, caps, exceptions in agent code, tool errors from the agent's own arguments. **Retry:** the run restarts from scratch, at most 3 attempts. **Analysed attempt:** the first that ends without an infrastructure failure; earlier attempts are recorded, not analysed. **Cost:** per-run outcomes use the analysed attempt; discarded attempts' tokens and time are reported per option. **Exhausted runs** have no outcomes and leave the primary denominators, are reported per cell, and in a sensitivity analysis count as time-capped (K) in the omission bounds and as failures in the end-to-end outcome. Attempts and failures per option are reported, since an option that fails more often is itself a finding |
| Pilot go criteria (symmetric; all required) | (i) the reference passes the equivalence validation; (ii) the read- and analysed-extent instruments reproduce scripted runs for every option; (iii) on scripted runs with known omissions and on the pilot's agent runs, the analysed-extent instrument labels no omitting run complete in any option, with at most 10% unknown. For the pilot runs, whether a run omits is decided by code inspection of all 30 runs, blind to the instrument's label, never by the instrument itself; (iv) the read records are calibrated by the day-0 checks (observability classes filed and timestamped before the calibration runs), and fault injection runs for every option and record. H3 is reported, not gated; (v) a scripted reference pipeline completes correctly through every option's data path; (vi) per-run wall time and provider I/O are measured, which sets the concurrency cap. Agent F1 in the pilot is a feasibility diagnostic, not a criterion |
| Instrument audit | about 100 runs per option, audited by code inspection, drawn with a fixed seed, stratified by model and by the instrument's label, with runs labelled omitting oversampled. False-complete and false-omission rates are re-weighted to the population and reported per option × layout with intervals. They are results of the study, used only in the sensitivity analysis of the contrasts |

## Rules (values after the pilot)

| Parameter | Rule |
|---|---|
| Period length and selection (**frozen 1 Nov** from #5's report) | **June–August** (92 days), the shortest candidate reaching 5–10 event-free instances; the calendar year gives none. Seed 20271. 8 event-free instances of 50: at most 1 per region (8 distinct regions) and at most 3 per year, redrawn until both hold. An event-free region's second period is an event-bearing year. The other 17 regions get 2 distinct event-bearing years. Pilot: 10 distinct regions, 2 event-free and 8 event-bearing. Calibration instance: the event-bearing pilot instance whose number of reference events is closest to the pilot median; ties go to the lower count, then the lowest id (I01). WAN anchor: 3 pilot instances, 1 event-free and 2 event-bearing. Required extent (ruling of 1 Nov on #9): sea cells × (the **method-required baseline window** ∪ the target days). The window is the union, over target days of year d and e ∈ [d−15, d+15], of all dates within ±5 calendar days of a 1992–2002 date with day of year e, on the 366-day month/day mapping. For June–August it is 12 May – 20 Sep of each year 1992–2002, 1,452 days. Analysing more does not compensate for any part of it that is missing; analysing beyond it is not required. Boxes: 25 disjoint boxes of 60 × 60 cells. **Eligibility (pre-registration correction, 1 Nov):** at least 95% of a box's finite cells lie inside the authors' Baltic sea mask (`BALarea`), and the box contains no inland water component of 10 or more cells (a finite component touching neither `BALarea` nor the grid edge, e.g. Vänern, Vättern); enclosed pockets under 10 cells are grid artefacts and stay. The first draw admitted two Norwegian Sea boxes (R22, R24); the boxes and every draw are re-run under this rule with the same seed |
| Percentile rule, pooling detail and method wording | **filled in on 1 Nov from #4** (Hazen; calendar-neighbour pooling including days just outside the baseline; day 60 interpolated; circular 31-day mean), the formal six-block Octave equivalence passed on 1 Nov. Fixed from #4: the estimator, the exact sample-selection rule (non-leap February, both baseline boundaries) and the wording with which our implementation is equivalent to the authors' code |
| Reference rule (**triggered on 1 Nov by #4; acknowledged by the operator on 1 Nov**; replaces the proposal's "uses the published threshold and climatology fields") | **Ground truth is always computed mode on the S1/S2 values the agents read**, with the frozen method. It is validated by **implementation equivalence**: the authors' code under GNU Octave, on identical data, meets the equivalence criterion below. **Agreement with the published catalogue** (thresholds against `m90`/`mclim`, events against the 189) is reported as description of the data-version effect, and is not a pass condition. Nothing is tuned to recover the 189 events |
| Prompt-faithful oracle | a literal implementation of the prompt must reproduce the ground truth **exactly** (identical masks and events). **Before registration:** on all 50 instances in S2 and on the 10 pilot instances in S1, through T, T-unpaginated, D and M; this has no fallback and blocks the freeze. The bytes each path delivers are proven equal by hash, so the method is tested on every instance. **After registration:** the other 40 instances' S1 cells complete, and any mismatch is reported in a results part |
| Calibration set | 7 models × {T, D, M} × {S1, S2} × 1 pilot instance × seed 1 = 42 runs at the provisional caps, run after the pilot. They are used only to set caps and are excluded from all analyses |
| `{TIME_CAP_MIN}` | the larger of (a) 2 × the **maximum** total wall time over all pilot and calibration runs, finished or not, and (b) 2 × the maximum over the six scripted cells {T, D, M} × {S1, S2} of the full-data run time at the concurrency cap (#12); rounded up to 10 min. The pilot runs at the concurrency cap, so its times include main-run model latency under load. It is the same for all options, so D gets no extra budget |
| Provisional caps during the pilot | generous and fixed in advance: 150 tool rounds, 4 M tokens, 240 min |
| `{TURN_CAP}` | max(40, 2 × the maximum number of tool rounds over all pilot and calibration runs), rounded up to a multiple of 10. A round is one assistant message with one or more tool calls. The cap triggers when the agent requests round `{TURN_CAP}` + 1; a tool-free final reply after the last allowed round is still allowed |
| Provisional-cap hits | if any run of a (model, option, layout) cell hits a provisional cap, that cap is doubled **once** and the whole cell's pilot and calibration runs are repeated; the values are then taken from the repeat |
| `{TOKEN_BUDGET}` | 3 × the maximum total tokens over all pilot and calibration runs, rounded up to a multiple of 10,000 and stated in the prompt as a plain integer. Total tokens = cumulative input + output tokens over all model calls in the run, including reasoning or thinking tokens and cached input tokens |
| Concurrency cap | the highest level in #12's curve at which **every** scripted cell {T, D, M} × {S1, S2}, with the audit log on, keeps ≥ 80% of its single-run throughput (≤ 1.25 × single-run wall time), with no errors and within disk limits |
| Equivalence criterion (our reference against the authors' code under Octave, fixed 1 Nov) | the reference computes in float64 with numpy `method="hazen"`, as the prompt instructs. Per validation block: (1) `m90`/`mclim` max \|Δ\| ≤ 1 float32 ULP at the field's magnitude (≈ 3.05e-5 K); (2) every cell-day whose event state differs lies within 1 float32 ULP of the threshold, with its count and share reported; (3) events identical except where such a boundary cell-day changes them, each case reported; (4) positive control: emulating Octave's single precision gives bit-identical results. **Clarification of (2), recorded openly on 1 Nov after the first blocks:** a ≤ 1-ULP exceedance can flip neighbouring cell-days through the 5-day and 2-day-gap rules, so a differing cell-day need not itself lie at the boundary. (2) is therefore tested by setting only the ≤ 1-ULP boundary exceedances to the authors' values and re-applying the run rules; it passes if no difference remains. The raw differing count, the at-boundary count and the residual count are all reported |
