1. **BLOCKING — [calibrate.py:720](~/work/wt/11-fault-batch/icsa/faults/calibrate.py:720): a lost run’s directory timestamp does not identify its lease window.**  
   A runs at `10..20`, releasing its slot at `20.5`. B creates its directory at `5`, waits for that slot, reads at `21`, then crashes, leaving a legacy empty directory. B’s reads fall inside A’s margin, but `lease_end <= directory_mtime` is false, so B does not invalidate A. In-memory reproduction returned no exclusion and assigned B’s read to A, potentially hiding A’s omission.  
   **Smallest fix:** treat directory creation as a lower bound on B’s possible lifetime; invalidate affected same-option neighbours unless actual lease bounds establish safe attribution. The early-directory expectation in `test_fault_batch.py:119` is unsafe.

2. **BLOCKING — [ranges.py:63](~/work/wt/11-fault-batch/icsa/faults/records/ranges.py:63): multipart bytes can still be credited as file data.**  
   The check counts ranges *after* dropping unsatisfiable members. Reproduction: `served_spans(206, "bytes=100-899,5000-6000", 800, 1000)` returns `[(100, 900)]`. A response to this multi-range request can still be multipart with one satisfiable part; its 800 body bytes include framing and need not contain the whole 800-byte chunk. The detector nevertheless credits that chunk.  
   **Smallest fix:** reject multi-range request headers before clipping away unsatisfiable members. The assertion at `test_fault_batch.py:368` explicitly preserves this incorrect inference.
