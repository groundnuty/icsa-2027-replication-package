1. **BLOCKING — interrupted runs bypass the scoring guard.** [calibrate.py:1011](~/work/wt/11-fault-batch/icsa/faults/calibrate.py:1011)  
   After `begin_run(sid)` followed by a crash, the ledger holds `started`, but `pending()` returns `[]`. With all other runs done, ordinary `score` proceeds without `--partial`, publishes other cells’ pass/fail results, and records no partial-score entry. Resuming `run` subsequently marks that same attempt lost and schedules its replacement. This violates replacement-before-scoring.  
   **Smallest fix:** include `_started(ledger)` in the scoring guard’s outstanding runs; keep `begin_run` refusing an already-started run.

2. **BLOCKING — one historical loss invalidates subsequent complete captures indefinitely.** [calibrate.py:609](~/work/wt/11-fault-batch/icsa/faults/calibrate.py:609)  
   In-memory trace: three source snapshots `[A] → [B] → [B,C]` produce `n_gone = 0,1,1`. The third pull lost nothing since the second, but `have` comes from the cumulative capture `[A,B]`, so the already-lost `A` creates another gap. Every subsequent pull repeats this. A fully recorded control between pulls two and three consequently changes from scored/clean to `not_observed`, keeping its cell incomplete. The first loss is correctly detected; the repeated gaps are erroneous.  
   **Smallest fix:** calculate loss against the previous source snapshot, using its retained hash capture. Continue using the cumulative capture for append deduplication.

3. **BLOCKING — malformed audit lines can still produce scored false alarms.** [calibrate.py:792](~/work/wt/11-fault-batch/icsa/faults/calibrate.py:792), [audit.py:68](~/work/wt/11-fault-batch/icsa/faults/records/audit.py:68)  
   A control reads two days. Its capture contains one valid open and another same-user open with timestamp `[2026-11-02 BROKEN]`. The second line fails the regex and is discarded within the two-line tolerance. Reproduction returns `audit_bad_lines=1`, `scored=True`, `detected=True`, with the second day missing. Counting the malformed line diagnostically does not invalidate the affected run. The first-pass fix works for matching-format timestamps such as November 32; these regex failures never reach it.  
   **Smallest fix:** retain malformed-line attribution information and exclude/count affected runs; conservatively exclude all possible runs when identity or time cannot be recovered safely.
